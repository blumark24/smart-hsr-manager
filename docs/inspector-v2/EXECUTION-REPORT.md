- Exact Preview SHA: **غير متاح؛ لا يوجد نشر تم التحقق منه**.

## ما أُنجز

استُبدلت لوحة المراقب بواجهة RTL مستقلة مستوحاة من الصورة، مع خريطة مدمجة وبطاقة حالة وشريط استشارة ومهمة حالية وإجراءات سريعة وتنقل سفلي. للهاتف توزيع رأسي وللشاشات الأوسع توزيع بعمودين. الشعار المعتمد محفوظ.

تعمل مسارات `#home` و`#tasks` و`#new` و`#statistics` و`#account` و`#map` داخل `inspector.html`. الدخول واستعادة مسار المراقب يشيران إليها مباشرة. `dashboard.html` صار مدخلاً توافقياً صغيراً يقود إلى V2؛ الواجهة القديمة محفوظة كملف نصي للاختبارات ومستبعدة من نشر Vercel. لا iframe أو Legacy modal أو CSS قديم داخل V2.

أُعيدت هندسة الحفظ إلى معاملة خادم تنشئ PENDING وتربط الدليل الخاص بالمؤسسة والمستخدم معاً. إعادة المحاولة لا تستبدل السجلات القائمة. حُفظت سياسة GPS بثلاث عينات مستقرة ودقة ≤30م وعمر ≤30 ثانية، وأضيف تحقق نطاق المؤسسة على الخادم. توثيق «بعد» يحفظ الدليل فقط دون إغلاق؛ لا يستبدل دليلاً سابقاً ولا يتجاوز صلاحيات الإسناد. AI وسبب الحالة ومسودة العمل تستخدم الخدمات المحمية الحالية وتبقى استرشادية. لا طقس أو SLA أو إشعارات أو شركات أو حالات قريبة وهمية.

التفاصيل الوظيفية في [FUNCTIONAL-INVENTORY.md](FUNCTIONAL-INVENTORY.md)، والعقود والقيود في [ARCHITECTURE.md](ARCHITECTURE.md).

## بوابات الإصدار

ستة بنود موثقة محلياً: عزل Legacy، المسارات، التحكمات المرئية، الحفاظ على البيانات، الاستجابة للأحجام المختبرة، وخطة التراجع. أربعة غير مكتملة: الأمان المتكامل، UAT، CI الكامل، وExact Preview SHA. **تقدير تقدم البوابات المحلي 60% (6/10)، وليس شهادة جاهزية Production أو نسبة مطابقة بصرية.**

P0 المرصودة محلياً: **0**، دون اعتماد شامل لبيئة حقيقية. P1 من عيوب V2 المثبتة بالاختبارات المحلية: **0 مرصودة**؛ لا يمكن اعتماد بوابة P0/P1=0 للإصدار مع غياب الاختبارات الفعلية. توجد **خمسة موانع إصدار ذات أولوية P1**:

1. عدم إجراء UAT على الخدمات والحسابات المصرح بها فعلياً، بما فيه الميدان وGPS.
2. تعذر اجتياز بوابة المحاكي والأمان المتكامل بسبب سياسة الشبكة.
3. CI العام غير أخضر: 116 إخفاقاً سابقاً يلزم حلها أو تقييمها رسمياً دون إضعاف العقود.
4. وصول بلاطات الخريطة والقبول البصري الفعلي لم يُعتمدا.
5. لا Preview مثبت بـSHA ولا smoke test أو rollback deployment موثقين فعلياً.

مرجع التراجع المصدرّي: `666e7d3`؛ مرجع التراجع التشغيلي يجب أن يكون آخر deployment سليم تم التحقق منه، وهو غير متاح هنا. خطوات الإصدار وsmoke/rollback غير الهدّام في [RELEASE-RUNBOOK.md](RELEASE-RUNBOOK.md). **لا نشر قبل إغلاق البوابات.**

## توصيات بعد اكتمال البوابات، مرتبة حسب العائد والأثر وتقليل المخاطر والتوسع

1. تثبيت CI ومحاكي معزول وUAT دوري متعدد المؤسسات، ثم مراقبة أخطاء الحفظ وقراءة الأدلة والتكاليف. أعلى عائد وأكبر تقليل لمخاطر التسريب والتشغيل.
2. بناء خدمة تكليف المراقبين ودليل المقاولين ونطاقات البلدية وSLA بعقود موثقة وتدقيق صلاحيات؛ يدعم التشغيل الفعلي والتوسع بين البلديات دون استنتاجات AI غير موثقة.
3. إضافة مسودة ميدانية محلية مشفرة وطابور رفع يدعم الاستئناف بمعرفات ثابتة وسياسة احتفاظ معتمدة؛ يقلل فقد العمل في ضعف الشبكة. الإصدار الحالي لا يدعي دعماً للعمل دون اتصال.
4. اعتماد مزود بلاطات مناسب لحجم الاستخدام، ومراجعة سياسات الصور المصغرة والتخزين والقراءات قبل التوسع. لا توجد خدمة مدفوعة أو التزام فوترة أُنشئ ضمن هذه المهمة.
